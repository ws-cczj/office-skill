# 从报告内容决定页面怎样画

正式开题稿在写逐页计划和试排时读取。这里补充源模板的内容适配方法；示意关系是设计例子，实际对象、条件和来源由本次材料确定，不沿用任何案例正文。

## 先从正文形成论证，再找表达方式

阅读详细报告后，先写实际文案，再选择模板页。内容去向记录须定位承担论证的具体信息及其落点。例如，实际用途为何要求改善某种响应，两组对照各回答什么，哪种观测可以核验哪个模型量。将它们对应到页面中的句子、图注或图上关系，并说明口述与省略的理由。以整节报告对应若干页的范围登记后，继续核对其中决定必要性、可比性和验证成立的内容。删页或合页时重新检查这些落点。图件来源清单和章节名称不足以完成这项核对。

本风格允许完整的短段落、比较说明和图旁解读。短标签用于导航和分层，不替代正文。将详细内容删成两三个名词，再放进宽大的卡片，不算提炼；先写清对象、动作、依据及限定，再通过分栏、局部图、表格或拆页安排阅读。文字不能独立解释的空间关系用图补充；图不能解释的研究必要性和方法理由用正文写清。

### 背景的内容底线

背景部分需让听众理解“在什么实际情境下，存在什么问题，已有研究或评价还缺什么，因此本课题准备从哪里切入”。可以用一页串联，也可以把需求与缺口分成连续页面；不固定四卡，不强制所有课题套同一种顺序。报告未给出的应用后果或研究空白不得编造。

对象结构图、输入与响应示意适合作为背景的解释材料，但仅有它们时该页仍是对象介绍。检查报告中用于说明必要性的具体正文是否被保留，而不是直接跳到技术路线。宏观场景可简写；关键的需求、困难和缺口应在页面能读到，不能全部移入口述。

## 为论证匹配证据与图件

报告提取文本不是素材准备完成的依据。把实际图、图注、表格、公式和正文放在一起读，为关键页记录“来源位置—提供的信息—采用/不采用的理由”。图件在正文中有提及但未提取到时，继续检查 DOCX 的内嵌媒体、矢量对象或原文渲染；不能直接把“未提取”写成“没有图”。不要求所有图上屏，也不以图片数量验收质量。

选择原图、自绘示意或文字对照，依据是要解释的关系：

| 要讲清什么 | 可采用的表达 | 尚未讲清的做法 |
| --- | --- | --- |
| 对象是什么、哪里发生作用 | 对象结构或装置图，标明相关部分、作用位置与本页观察对象 | 只列“输入—响应—评价”几个词，听众仍看不到研究对象 |
| 两种模型有什么差别、怎样比较 | 两个实际模型的简图或原图，共用条件就近列出，用对应线连接可比较的量 | 两个大框分别写“模型对照”“瞬态响应”，中间放箭头 |
| 工序怎样改变样品或状态 | 对象随步骤的变化，步骤之间注明送往下一步的样品、数据或模型 | 各步骤只有方法名称，箭头没有说明传递什么 |
| 对照是否公平、怎样判断 | 显示对照组、保持一致的条件、实际观测量和材料支持的判断依据 | 只写“对照验证”“比较峰值”，漏掉左右可比的条件 |
| 工作怎样组成目标 | 总目标与分目标、任务与交付的对应，必要时用分支或汇合 | 将目标、任务、关键问题写成同一组三栏，只更换标题 |

文字对照适合比较定义、限制或条件。需要解释几何、空间位置、边界、局部结构或装置时，普通文字框不能完成同样的工作。缺少实测图时可以绘制标明用途的概念示意；不得编造实验曲线、数值或“已验证”结论。

## 三个可供选择的构图例子

### 对象与问题页

可从源 02 或 03 页适配。主图展示对象及相关局部；旁侧说明实际需求、已有认识和本次缺口，底条收束研究切入。对象图可用原图，也可用可编辑的轮廓、部件、局部引线和标签重绘。箭头分别表示作用、观察或放大时要能区分。若材料支持多组同类证据，也可用并列证据构图，不必强行单图。

逐页计划须写到能绘制的程度，例如：

- **问题**：听众需要分清整体对象与待研究的局部，才能理解后续比较。
- **主图**：报告中已核实的结构图；实际文件、图号和裁切范围写进素材清单。自绘时逐一列出主体、局部、边界、作用位置和标签，注明依据与示意状态。
- **关系**：由整体上的标记引到局部；说明卡各解释图中一个位置，底条承接该位置尚未解释的问题。
- **取舍**：在上屏文案中保留具体需求、困难及研究切入的依据；应用案例的展开和重复解释可放口述。逐页稿写出实际句子，不能只写“需求、问题、意义”等标签。

“问题与落点：研究背景”“主阅读关系：四个阶段的文字列表”不足以交给绘制步骤使用。

应用名词只说明研究出现在哪些场合。应用或学术需求承担动机时，在正文留一句连接“实际关切 → 现有证据解答到哪里 → 此研究为何选这个切口”的解释。它可以由相邻页接力。比较的评价量如果各自独立，就并列展示；流程箭头留给有先后或依赖依据的关系。

### 模型或方法对照页

可从源 04、07 或 10 页适配。选择原模型图、带边界的几何简图或分层方法结构图。两个模型采用可比的视角和标注，用局部对应线、共同输入或统一比较区组织阅读。左右不是先后工序时，不添加暗示先后或因果的单向箭头。

逐页计划写清：各图保留哪些差异；哪些几何、材料、边界或输入条件必须一致；比较量分别从哪个位置或输出取得；怎样表述适用范围。条件由材料提供，不自行假定所有项都相同。没有计算结果时展示验证设计，不能绘制看似真实的吻合曲线。

绘制后核对画面所表达的关系。标题承诺“对应”时，能沿引线指到两个实际对象及各自的量；标题承诺“区分”时，各组能读出自己的输入、观测和用途；标题承诺“机理”时，符号、形态及作用位置都能指认。关系需要两类对照回答不同问题时，保留每类的输入、共用条件与判断对象，即使两类对照共享一张图。

对照中的共用条件与按工况变化的条件各自就近标明。机制页可在同一视觉区域并列两条路径，把作用对象或关键量放到各自路径起点，再说明怎样核验响应。只有文字分组和汇聚箭头时，按标题核对该页实际展示的是核算分类、步骤还是物理机制。时间顺序与机制同时出现时，两者有各自清楚的图注和位置。

### 制备或实验验证页

可从源 06、10、12 或 14 页选择组件。工序页可以是样品状态转换，验证页可以是“对照对象＋观测位置＋比较量”，整体与局部页可以是主图加放大图。布局可左右交换、增减分支或拆页，维持藏蓝短标签、细实/虚线角色和卡内层级。

逐页计划写清实际样品或组别、保留的变量与共同条件、观测方法、数据去向。若用两幅图，就说明对应位置与尺度；若用流程，就给关键边注明传递的样品、数据或参数。每个箭头都能在讲稿中解释。相邻方案研究对象不同，先检查各自需要的图，再考虑是否能复用同一种构图。

## 从源模板复用到实际试排

先查[共用框架与正文组件](proposal-workflow.md#共用框架与正文组件)，用本次读法决定能否整页复用。局部适用时重组组件，例如“保留左短标签与虚线证据框，右侧改为整体加局部，比较条件放图下”。需要重绘正文时，可从已调好的导航和标题起始页继续，按真实图幅和讨论顺序安排内容。检查所用短标签、虚线证据框、浅灰说明区的层级，同时核对图上实际对象及标注。

源页的卡高、栏宽和图槽面积由本页文字与证据决定。正文可采用分层短段落、就近图解、整体与局部对应或条件比较。目标分解和任务汇聚即使共享三栏，也应各自表达相应关系。脚本复用绘图函数时，各页仍须能单独设置正文区域、图件比例、标注及连接；逐页核对共用构图是否足以说明本页内容。参考成品中的论证段落、图旁解释和指图顺序可以迁移，文字量和原图内容由本次任务决定。

在批量绘制前，选择最能暴露难点的技术正文页试排。查看实际导图后逐项回答：

1. 不看讲稿，能读出本页的主张、依据及必要条件，还是只能认出主题？关键文字是否按清楚的阅读顺序组织？
2. 能指出研究对象或证据在哪里，图旁说明是否解释它为何支持本页论证，而不只是重述标题？
3. 对照、边界、输入输出和来源是否保留到足以理解，箭头是否表达正确关系？
4. 容器、字级、细线和留白是否服务这些内容？

技术图先对照来源确定作用对象、实际边界及方向。共用界面用两物体实际相接的范围标出，界面作用的标记连接这段边界。验收时沿每个符号指出作用端及其所指对象。一个图形只承担它实际画出的含义，例如曲线可以标出初始弯曲，偏心则需要独立可辨的位置关系。简化图可取本页必需的关系，保留来源给出的限定。机制图展示作用与响应的关系，时间轴用于指示时间顺序。并列比较量采用并列标注；力矩、转角和位移采用可辨的不同符号。

未解决的内容缺口先处理再扩展全稿。背景等论证页也要试读，不能只试排图最复杂的一页。留白不按占比硬填：若大框只装了几行普通名词，先对照原文检查必要解释是否被删掉，再决定补回内容、缩短容器、换构图或拆页。不能仅以缩小容器掩盖内容缺失。

## 质量判断与讲稿

最终逐页记录实际观察。例如“主图标明两个模型的共同边界，右侧比较表列出同一输入下要核验的量”。只有“原生形状可编辑”“没有超框”“检查器无告警”不能证明这页讲清楚了。重复构图本身可以合理；若多页都没有可指读对象，只换名词，就需返修。

讲稿沿实际图解释术语、位置、比较理由和判断，再转入下一页。独立稿与备注一致只证明文件同步；一两句概述仍可能无法支撑技术页的现场讲述。用户未给时长时不强凑字数，也不能把摘要当成完整解释。

最终导图后检索讲稿中的左/右、上/下、虚线/实线及颜色指代，在实际画面逐个指认。区分外侧装饰图框和图内具有技术含义的区域边界；逐页稿、独立稿、备注可能同步包含同一个错误，不能只比较三份文字。修订图件后使用同版本导图复验，不以旧拼图的缺陷否定已修复页面。

验收分别记录文件/功能、内容表达、视觉适配。任何未解决的问题具体到页码；不能在完成后以“只是汇报提纲”“完整细节见报告”为由，将原先要求的正式汇报降级并判定合格。
