# 风格复现与页面验收

在使用风格参考、从零复现模板或终检时读取。这里规定如何把视觉要求落实为可观察结果；具体字体、字号、比例由当前模板和内容决定，不给所有学术页强套同一组参数。

## 先确定哪些特征必须保留

区分用户要求的是接近复现还是自由改编；明确参考时默认保留可辨认的关键特征，日常文字与章节数量按本次内容调整。只记录会影响生成的要点，在任务 `style-contract.md` 中用下列列项表达即可：

`组件/参考区域 | 必须保持的特征 | 可调整项 | 实现与估计参数 | 验收方法 | 未知项`

- 轮廓及连接：高亮是独立按钮还是与背景边缘相连的异形区域；曲线方向、切口、开口和连续边界。通用圆角矩形不能默认代替所有异形标签。
- 比例：标识区、当前章、其他栏目的相对宽度，页头与内容区的高度关系，字面占栏目的比例。用相对值说明截图估计，不能假称得到原始 PPT 参数。
- 字级：中英文的相对大小、字重、颜色与换行方式。区分原图文字、模板文字及可编辑栏目提示；精确字体未知时写明替代字体。
- 材质与细线：连续渐变的方向、起止色及过渡；实/虚线边框的用途；细竖分隔、圆角大小与阴影。连续渐变须采用真正渐变填充，不能以几个纯色色块硬切模拟后称为一致。
- 状态与内容：当前章切换、不同章节数量下的适配；正文、指标、校徽、作者属于任务数据，使用占位或本次实际材料。没有校徽时调整空间或留中性占位，不擅自增加更大的品牌块破坏比例。

截图的工具栏、缩略图列、水印和浮层排除在模板之外；被遮挡的细节保留未知。普通图片压缩和截图锐度差异不当作风格错误。

## 局部组件先验证，再铺到全稿

在已授权的 PPT 生成任务中，若复现难点是跨页重复的导航、标题条或证据卡，先在本次工作副本验证该组件及一张代表正文页。使用占位标题、长标题和至少两个章节状态；导出 PNG，与参考的同一局部在接近尺寸下对照。普通可编辑形状、自由曲线或组合均可，选择能保留关键轮廓的方法；不要整条截图铺图代替可编辑组件。

核对轮廓、连接关系、相对比例、字级、间距及细线后再批量复用。不强制停下来请用户批准中间样条，也不将内测组件自动入库。若用户本轮仅要求分析或明确延后示例，则只写规则与待验证项，不创建 PPT。

功能验收与视觉验收分别记录，例如“导航高亮切换正确”不能证明“高亮轮廓与参考一致”。不能实现的关键细节记录为偏差，先修复；无法修复时如实交付限制，不自行宣布风格已验证。

## 正文版式也要匹配

正式汇报先对照本次用户要求和逐页稿，检查布局是否表达了主次、并列、流程、分解或汇聚，再核对导航、标记、线型和视觉层级。出现篇幅、图幅、正文条件或证据数量与源页预设冲突时，检查是否已扩栏、重组组件或拆页，以及修正后关键依据是否可读。连续多页共用正文时，逐页核对是否确有相同的阅读关系。版式验收以正文适配、风格特征和用户明确指定的布局为依据。

组件按用途保留差异：证据框与任务框的实/虚线、圆角尺度、标签宽度及与边框的连接、内层浅色区、箭头和分隔线的阴影。检查实际渲染中的继承效果；关闭普通矩形阴影不代表连接线已无阴影。不要把截图拼图的外部阴影学进幻灯片内部。

留白与真实内容一起判断。内容较少时可缩短容器、合并相邻说明或调整版式，不机械塞满，也不保留大量无用途的同型空框。没有真实证据图时不虚构图表来复制密度；使用任务允许的示意或明确标记布局适配。

面向观众的标题和说明只承载主题、事实、结论及必要限制。指导 Agent 如何写作、审核或避免错误的过程话语放到备注/QA，不直接充当页面副标题；真实的研究状态和不确定性仍需清楚披露。

## 文本填充后的实际布局

内容填充工具可能改变框高、自动适应或段落格式。操作顺序：记录布局 → 填内容 → 设置中西文字体/字号及段落 → 必要时重新获取对象并恢复位置和尺寸 → 回读文字边界 → 导出检查。不要只核对绘制脚本里的参数。

可通过内置工具的 `snapshot` 或本次 COM 脚本回读对象尺寸与 `TextFrame2.TextRange.BoundLeft/BoundTop/BoundWidth/BoundHeight`，结合内边距判断实际文字边界；不支持的属性标记未知。对边界告警再看最终 PNG，不以“形状在画布内”代替文字适配检查。

- 避免中文词语拆断后留下单字尾行；短尾行优先改宽度、合理断句或在不改含义的前提下压缩文案。
- 长标题优先调整区域、允许两行并联动正文起点；确有需要才适度调整字号。不把禁止换行作为通用修复，更不能造成文字在框外却侥幸可见。
- 密集页检查内容区、来源与页脚是否冲突。来源、图表标签仍需在目标显示尺寸可读。
- 自动检查告警分为“确认问题”“工具估算/继承解析差异”“未验证”，附页码与证据；既不把每条告警都当成裁切，也不因截图暂时看似正常忽略框尺寸异常。

## 图表与可编辑性

每个关键图表在文稿或素材记录中标明模式：

| 模式 | 可编辑范围 | 检查 |
| --- | --- | --- |
| 原文图像 | 整体尺寸与裁剪，图内数据不可独立改 | 比例、单位、标尺、图例、误差棒及统计标记未误裁 |
| 原生形状示意 | 柱、线、标签可逐个编辑，无自动数据联动 | 坐标与数值对应，不能称为有数据系列的原生 Chart |
| 原生数据图表 | 系列和数据可改，图随数据更新 | 有实际 Chart/数据系列，修改一项测试数据并恢复后验证联动 |

对原论文定量图的重绘保留误差范围、样本量和统计语义；没有准确值时用原图或保留完整证据图辅助，不能猜误差棒。简化图须说明省略了什么，不能仅展示三点就把未展示区间的平台或最优值当作图中直接证据。精确数值和研究主张可回溯到来源页/表/图。

快照的类型名称只是辅助线索。某些服务版本会将文本框或连接线误标为图片/OLE；遇到与视觉或脚本矛盾的类型，核对原始类型值、HasTextFrame/HasChart 与 PPTX 内对象结构，必要时做编辑保存重开验证。不得据错误标签判定已栅格化，也不得只数形状就断言所有图表均可编辑。

## 修改与最终交付

保留原版并另存修改版。根据稳定 ID 修改目标对象，同步文稿、布局与备注；检查导航、页码、连接关系。对未要求修改的页面比较文本、对象位置、尺寸和样式；必要时比对页面 XML（相同可证明未改，不同须查原因而非直接认定回归）。

`qa/report.md` 简洁记录：最终路径/版本、检查过的页、风格关键特征、内容来源核对、文本与对象问题、修复结果、原生图表/形状/图片的编辑范围及剩余限制。只对受影响页重检，再确认终版全稿顺序和关键跨页元素。不要以“文件生成成功”“对象未越界”或“零自动告警”代替视觉验收。

## 正式汇报验收

成品以实际导出图逐页判断。生成会话发现问题后修正对应页和发言稿，再重新导出检查。训练管理者在同一份证据上记录未达项及后续规则修订。仍无法确认的项目在交付中注明页码和缺口。

| 检查项 | 如何判断和修正 |
| --- | --- |
| 内容完整与可读 | 先隐藏讲稿，阅读实际页面，检查主张、支持信息和必要限定是否能读懂；再对照报告的重要内容去向。章节齐全、图已插入、文字不超框均不能证明论证完整。背景只剩对象图、整页只有标签、关键理由全在讲稿时，先重写内容再排版。文字过密则分层、重排或拆页，不能靠挤字或删掉必要论据通过。 |
| 图件与证据 | 比较、流程、机制、局部放大等关系有能读懂的图件或与内容匹配的文字对照。研究对象、几何、边界或观测位置需要可视化时，检查图上能否实际指出这些对象；普通文字卡及几个方法名加箭头不能代替。核查自绘示意的标签和原图的图注、比例。 |
| 叙事与来源 | 每张正文页有独立的作用。相邻页重复时合并，或明确各自讲目标、任务、验证中的哪一环。核实题目、单位、证据状态及进度。逐页检查底边及图注是否混入报告定位、制作或验收说明。内部溯源写入工作稿和 QA。上屏的文献归属贴近对应证据，页底只留风格元素和所需页码。 |
| 模板细节 | 目录与导航章名、顺序、高亮同步。查看中文和英文实际可见，白色异形与页顶连续相接，关键线型和正文图文层级清楚。文字边界回读和导出图均检查。 |
| 口述与文件 | 对照最终 PPT 页序核对独立讲稿与备注，指图文字对应实际图位。保存后重开，确认原生对象仍可编辑，导出图和讲稿对应同一版。 |

在验收记录中写能从最终画面复核的观察，如“第 6 页右图的引线从主图的框选区域接到局部放大图边框”。关键关系按需要指出连线两端、关键条件的所在位置或实际可读的文字。计划或对象存在只能证明有制作意图或放置对象，画面未显示的关系记为未达。同一成片的制作会话可记录修正和重导结果，管理者验收时记录页码、画面证据和需要调整的规则。

分别给出文件/功能、内容表达、视觉适配的结论。背景未建立研究必要性、正文的重要论证被删空、技术对象缺失、对照条件丢失或整段方案仅剩提纲时，属于内容返工，不能仅列为标注和对齐的局部精修；不能用“提纲”“细节见原报告”降低原任务要求后宣布通过。讲稿与备注一致仅证明同步，另查讲稿是否解释图、术语和比较依据。

### 试排与导图核对

从当前风格的复发项和本次材料选最有风险的正文页。把预计的主张、必须在画面找到的依据或条件，以及决定图义的关系写进已有逐页稿。模型对照可写成一个可回答的问题，如“同一截面在两种表示中分别对应哪里，哪些量在同条件下比较？”

打开 PowerPoint 的实际导图，先据画面写出答案和具体位置，再同逐页稿、报告原文及图注核对。实际答案落不到图上或文字中，就定位文案、绘图输入、图义或排版的第一处缺口，修订对应材料并重导。把页码、导图、观察和复核结果记入已有 QA，例如“右图可指认局部对象，但对应线落在框外，待重导复核”。单独核对相邻页或共用组件是否继承同一缺口。

放大难页的关系图，逐根跟到线端，确认它落在指定对象、节点或边界的实际范围内。作用方向、示意引线、对应线与转角使用可辨的符号或图例。长线遮住标签或箭头尖碰到文字时调整位置。放大卡片末行，核对字面与边框之间的实际留白，优先调整措辞、断句和尺寸。图块改位后，按终版画面复核逐页稿、备注和 QA 的方位指代。标题、图注及备注面向观众，制作过程记录放在工作稿或 QA。

终稿再用同一问题检查试排页及其关联页。结论应指向可读的画面证据，例如某条引线两端实际相连、某个关键条件位于图旁对照区。报告中仍缺证据的说法应收缩到可证范围，并交代影响。文件检查结果仅用于其已列范围。

### 从文件核对三类问题

使用 [check_deck.py](../scripts/check_deck.py) 读取最终 PPTX。工具默认提示正文和备注中的常见内部措辞及路径，包括「依据：开题报告 §…」和「制作说明：…」。文本命中需结合页面用途判断，图片内文字和其他表达仍需看终版导图。按任务传入适用参数，使用本次实际路径和页码。下例中的月份来自报告的计划终点，页码来自成品页序。

```powershell
python -X utf8 scripts/check_deck.py output/汇报.pptx --source-template resources/article/proposal-navy-navigation/template.pptx --timeline-end 12:2028-04 --speaker-script output/发言稿.md --content-pages 3-11 --output qa/deck-check.json
```

- `--source-template` 检查沿用源位置与尺寸的图位。保留原图框但前景只有文字时会提示。有原图、图表或新绘形状仍需确认表达内容有效。重排为正文文字对照后可移除原图框。移动或更名的旧图位用实际导图检查。
- `--timeline-end` 核对指定页最晚的可读 `YYYY.MM` 类月份标签。每个相关时间轴可传一次。日期与时间条位置的对应关系仍需看导图。
- `--speaker-script` 对照独立发言稿和同页备注正文。`--output` 保存检查结果和当前 PPTX 的哈希。退出码 `0` 表示已运行的检查通过，`1` 表示存在待复核项目，`2` 表示输入错误。误报应写明实际页与理由。成片内容变化后用最终文件重跑。
- `--content-pages` 指定真实正文页，例如 `3-11` 或 `3,4,8-10`，排除封面、目录和文献。按画布高 15%–95% 区间统计正文图片、图表/表格、分组及大容器；三页以上重复大容器且无这些对象时提示看图复核。该近似区间不适合所有模板，可不指定或按实际页另行核查。原生图形也能表达有效示意，分组、插图或换颜色也不能证明有技术内容；提示本身不裁定错误。删除/重命名原图位不再是规避这项提示的途径。
- 报告中的 `quality_verdict:not_assessed` 始终表示工具没有判断成片质量。结构检查、空图位检查和正文容器提示都有边界，不能合并改述为视觉与内容已验收。
