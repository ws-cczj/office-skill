# 桌面 COM 与 QA 共用约定

应用入口保留在各自子 Skill。共享模块承载进程协作与验证约定。[office_batch.py](office_batch.py) 为 Word 和 Excel 提供计划入口、私有 COM 实例、工作副本、保存重开与产物发布。应用对象模型仍由各自模块处理。

## 环境与桌面协作

- 先检查 Windows、Python 3.10+ 和 pywin32，再按应用入口实际连接已安装的桌面软件。分别报告依赖状态、连接状态和失败原因。依赖探测成功只代表可以尝试连接。
- COM 入口在连接应用前持有 [DesktopLock](desktop_lock.py)，锁覆盖目标绑定、修改、保存、重开、导出和本批清理。共享默认锁是系统临时目录下的 `ppt-skill-desktop.lock`，沿用文件名以与既有 PPT 副本互斥。锁被占用时退出本批，待桌面空闲再按实际状态继续。
- 此锁约束使用同一临时目录并遵守协议的进程。其他桌面客户端和用户操作仍需协调。按完整绝对路径绑定工作副本，保留无关文档和用户已打开文档的生命周期。

## 保存重开与交付检查

保存工作副本后，从交付路径重开已保存版本并回读受影响对象，再用原生应用导出用户实际收到的预览。只关闭本批拥有的文档。Word、Excel 修订指定 `update:true` 和现有工作稿。在同卷的临时区处理并验证后，写回同一工作稿和指定导出；失败时清理暂存。中断或报错后先核对已落盘状态和已完成操作，再处理剩余部分。

文件校验可离线只读解析已保存产物。按明确输入和参数报告检查范围、可定位的事实与告警，固定输出 `quality_verdict: not_assessed`。如需持久化报告，另写到 `qa/`，保护输入文件和成品。最终报告分别记录文件校验、保存重开和实际视觉审查的结果。
