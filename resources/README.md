# PPT 模板资源规范

资源库用于登记风格、按用途浏览并生成可编辑 PPT。当前 [学术风格](article/README.md) 包含已验收的藏蓝导航源模板和待验证的蓝白渐变风格。下文示例 YAML 仅说明格式。

模板定义只包含视觉样式、版式结构与占位符，不绑定具体论文、研究结论、作者、数据或机构。可使用 `[标题]`、`[正文]`、`[图片]`、`[图表及来源]` 等占位展示；章节和栏目名称可以作为可编辑结构提示。固定校徽、作者身份和截图水印不作为通用模板元素保留。后续示例文稿用于展示效果，与空内容模板分开保存。

可分发资源由各风格包的规范、元数据和通用模板或预览组成。材料、个人报告、旧稿及原始训练证据存于忽略的本地工作目录。生成读取当前任务材料与风格包，`learning.md` 中每条规则应能独立执行，包内引用使用相对路径。

从截图制作空内容模板时，按 [模板制作与验收](../references/template-workflow.md) 识别并去重页型，每种独立版式保留一张可复制页面。同一页的用途可以由多个版式承载。正式汇报根据主张、证据数量和图文关系选择、组合、调整或新绘版式，并沿用该风格的视觉特征。

只有截图时可以先归纳候选风格规则，明确哪些属性来自观察、哪些是建议值；无需立即生成 PPT 或展示样例。此阶段仍为未验证参考，不能将原始截图冒充本 skill 的生成预览，也不能标为 `ready`。用户要求延后示例时，待以后实际用本 skill 做出满意结果后再生成正式展示图。

## 分类与目录

```text
resources/
├── README.md
├── article/                   # 学术：论文解读、组会、开题、答辩
│   └── <style-id>/            # 有实际资源时创建
│       ├── template.yaml     # 身份、适用范围、能力、验证状态
│       ├── preview.png       # ready 必需；对应版本的真实页面总览
│       ├── style.md          # 可执行的排版与风格规则
│       ├── learning.md       # 可复用的分析结论、已知问题、修正与复验状态
│       ├── maintenance.md    # 可选；源模板的编辑和复验说明
│       ├── template.pptx     # source 模式必须提供
│       ├── sample.pptx       # rules 模式达到 ready 时必需的验证样例
│       └── validation.md     # 验证范围、结果与对应版本
├── work/                      # 周报、项目汇报、工作总结
└── education/                 # 课程讲解、课堂作业、教学展示
```

场景决定叙事需求，风格决定视觉表达。目录表示主要用途，不禁止跨场景使用；次要用途记录在 `use_cases` 中，不复制一份相同模板。细分场景先用标签表达，需要时再扩展分类，避免过深目录。

`article` 依照本项目约定作为学术类目录名，不限于单篇论文。`<style-id>` 使用稳定的小写英文与连字符，完整 ID 为 `<场景>/<style-id>`。旧文稿中的 `academic`、`business`、`classroom` 场景名称可分别映射到 `article`、`work`、`education`，不要求批量改写历史文稿。

## 模板信息

每个风格用 `template.yaml` 保存元数据，不额外手工维护一份重复的模板清单。下面是字段示例，不能原样作为可选风格发布：

```yaml
schema_version: 1
id: article/example-style
name: 示例风格（格式示例）
version: "0.1.0"
status: draft                  # draft / validating / ready
scenario: article
use_cases: [论文解读, 组会汇报]
description: 用一句话说明视觉特征、内容密度与适用任务
aspect_ratio: "16:9"
mode: source                   # source / rules
preview: preview.png
style: style.md
learning: learning.md
source: template.pptx          # rules 模式填 null
sample: null                   # rules 模式填 sample.pptx
page_types: [cover, agenda, text-image, chart, summary]
fonts: [Microsoft YaHei]
editable: [text, shapes]       # 只填写已验证对象类型
limitations: []                # 未支持能力、字体或版式限制
provenance:                    # 源模板和随附素材的来源与使用范围
  origin: null
  usage: unknown              # 如实填写，不默认代表已获授权
validation:
  version: null               # 必须与当前模板版本相同才可 ready
  report: validation.md
```

字段中的文件路径相对于该风格目录。`source` 模式使用可编辑 PPTX 模板；`rules` 模式依据 `style.md` 绘制。达到 `ready` 时，两种模式均须有真实预览、规则和验证记录，rules 模式还须提供通过检查的 `sample.pptx`。

`draft` / `validating` 风格可以先登记 `template.yaml`、`style.md`、`learning.md`、`validation.md`，将尚未生成的 `preview`、`source`、`sample` 写为 null，`editable` 不填未经验证的能力。此阶段 `page_types` 表示计划复现的版式，`fonts` 表示实施替代字体。初始设计截图及原始分析证据归档到本地分析器，风格包保留文字结论和可复用规则。

`style.md` 应说明画布和安全边距、字体与字号层级、色值、段落与栏间距、典型页面布局、图表和图片规则，以及内容超量时的拆页或压缩策略。记录可执行数值、对象关系和能力边界，不只使用“简洁、科技感”等形容词；源模板已有规则时可引用其母版或布局，但须通过实际读取确认名称。

还须区分“必须保持的风格特征”和“可调整项”，并为关键组件记录参考区域、轮廓连接、相对比例、字级、边框/渐变/分隔细节及验收方法。截图估计值与实测值分开标记；“允许近似”不意味着可以丢掉异形连接或把连续渐变换成硬切色块。执行与验收见 [风格复现与页面验收](../references/visual-quality.md)。

## 预览与可用性

`preview.png` 建议是 4–6 个代表页面的拼图，包括封面、正文、图表和总结；只展示模板实际支持的页面类型。每格保持原比例，标题与主要内容清晰可辨。来自同版本的 `template.pptx` 或 `sample.pptx` 实际渲染，不能使用无法复现的效果图或带调试标注框的截图代替。可按需附加单页预览，首版无需维护多张选型入口图。

模板通过以下检查后才能设置 `status: ready`：

- 必需文件存在、可读取，ID 与目录一致；预览与验证记录对应当前版本。
- 在目标 PowerPoint 环境生成或填充代表页面，验证中文、内容密度、图片裁剪及声明支持的图表等页面类型。
- 实际查看最终导出图，检查溢出、遮挡、换行、对比度、引用与页码；修改后重新导出。
- 将重复组件的实际导出局部与参考对照，逐项验证风格关键特征；导航功能正常不能替代造型、比例及字级验收。未达到的关键特征记录为待修，不能标记 ready。
- 验证声明的可编辑对象并保存重开检查。`validation.md` 记录版本、环境、样例文件、覆盖的页面类型、结果和未覆盖能力；字体替代及其他限制写入元数据。
- 记录源模板与随附素材的来源和使用范围；存在明确禁止分发的内容不进入内置库，未知项如实保留并说明适用限制。

`ready` 是针对已记录环境和能力的验证状态，不保证任意内容都能直接套用。生成新文稿仍需按任务检查。影响排版或能力的资源修改后，更新版本并退回 `validating`，重新验证与导出预览后再开放选择。

## 选择与使用

1. 根据用途读取对应场景下的 `template.yaml`，按状态检查必需文件。目录名、PNG 存在或 `ready` 标签本身不足以证明可用；ready 的验证版本不一致或必需文件缺失时，从正式选型中排除并报告。draft / validating 按上文登记要求检查，不套用 ready 的 sample/preview 要求。
2. 正式选型按用途、比例和所需页面类型筛选实际可用的 `ready` 风格。用户浏览时展示其 PNG。查看开发进度或指定复现测试时，可展示已登记的 `draft` / `validating` 风格，并说明当前验证状态与可用预览。
3. 用户已指定模板时直接使用该记录。指定待验证风格用于测试时，按对应风格规则和学习记录试制。生成请求未指定风格时，根据受众和用途代选，优先 `use_cases` 明确匹配且有合适视觉组件的 `ready` 模板。同等适配时优先可复用对象的 `source`，将选择及依据记入本次运行简报。当前开题与研究方案默认用 `article/proposal-navy-navigation`。用户要求浏览或自行选择时再展示候选预览并等待其选择。候选使用稳定 ID。
4. 选定后从 `template.yaml` 读取 `style`、`learning` 和可用的 `maintenance`，将 ID、版本、原始路径与适用的学习条目记录到 `runs/<run-id>/`。复制所需资源到任务目录，按[模板复用规则](../SKILL.md#按内容复用模板)选用组件或页型。`page_types` 是源文件或规则中可用版式的索引，正式文稿的章页清单由本次任务给出。任务内容与成片留在该次运行中。
5. 用户要求使用某个特定的视觉模板但该模板缺失时，报告具体缺口并继续整理可用材料。普通生成请求无适配的内置风格时，按用户提供的模板制作，或按场景规则绘制，并在交付中写明实际采用的方式。

以上是 Agent 执行约定，目前没有实现独立模板浏览器、自动扫描器或验证器。

## 每轮学习怎样落到风格包

- 在 `learning.md` 用稳定 ID 记录问题与日期、适用页型、具体修正、复验方法和实测范围。已找到同类条目时更新该条，避免形成多份不同版本的做法。版式细节变化同步到 `style.md` 或该风格的制作指南。
- 通过后写明验证的模板版本、页型和内容范围。只补了规则的条目标为待复验，空模板的通过只覆盖空模板所测的项目。检查本次导出时核对适用 ID 和实际页码，复发项修完后再查该页。
- 原始截图、私有正文、成片和对象提取留在本地分析器或运行目录。资源包只带可复用结论、规则和经独立验收的正式模板资产。

## 后续自定义风格

后续入口可接收提示词、参考图片和内容要求，在任务目录形成候选风格规则与样例，经过实际生成和验证后供当前任务使用。用户明确要求收录且资源可复用时，再按本规范入库；不自动把私有资料变成公共模板。

当前阶段称为“模板调优与生成验证”。若以后实施模型训练，另行记录数据范围、训练方法和评估结果，不把修改提示词或增加样例报告为已训练模型。
